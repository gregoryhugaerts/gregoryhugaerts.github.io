General-purpose, statically-typed, object-oriented language developed by Microsoft in 2000. Runs on the .NET platform — compiled to CIL (Common Intermediate Language), executed by the CLR (Common Language Runtime). Multi-paradigm: OOP at core, with strong functional features (LINQ, lambda, async/await).

Primary domains: web (ASP.NET Core), game development (Unity), Windows desktop, enterprise, and cloud (Azure).

Classes and OOP

CSHARP 
public class User
{
    // Properties (auto-implemented)
    public int Id       { get; set; }
    public string Name  { get; private set; }
    public bool Active  { get; init; }   // init-only (C# 9)

    // Constructor
    public User(int id, string name, bool active = true)
    {
        Id = id;
        Name = name ?? throw new ArgumentNullException(nameof(name));
        Active = active;
    }

    // Method
    public string Greet() => $"Hello, I am {Name}";

    // Override
    public override string ToString() => $"User({Id}, {Name})";
}

// Inheritance
public class AdminUser : User
{
    public string Role { get; set; } = "admin";

    public AdminUser(int id, string name) : base(id, name) { }
}

// Record (immutable, value semantics — C# 9)
public record Point(int X, int Y);
var p1 = new Point(1, 2);
var p2 = p1 with { Y = 5 };   // non-destructive mutation

Interfaces and Generics

CSHARP 
public interface IRepository<T>
{
    T GetById(int id);
    IEnumerable<T> GetAll();
    void Save(T entity);
}

public class UserRepository : IRepository<User>
{
    private readonly List<User> _users = new();

    public User GetById(int id) =>
        _users.FirstOrDefault(u => u.Id == id)
        ?? throw new KeyNotFoundException();

    public IEnumerable<User> GetAll() => _users.AsReadOnly();
    public void Save(User entity) => _users.Add(entity);
}

LINQ

Language-Integrated Query — query collections with SQL-like syntax or fluent method chaining.

CSHARP 
var users = new List<User>
{
    new(1, "Alice"),
    new(2, "Bob"),
    new(3, "Alice")
};

// Method syntax (most common)
var activeAlices = users
    .Where(u => u.Active && u.Name == "Alice")
    .OrderBy(u => u.Id)
    .Select(u => u.Name)
    .ToList();

// Query syntax
var result = from u in users
             where u.Active
             orderby u.Id
             select u.Name;

// Aggregation
int count = users.Count(u => u.Active);
var grouped = users.GroupBy(u => u.Name);
var first = users.FirstOrDefault(u => u.Id == 1);

// ToList(), ToArray(), ToDictionary() materialise the query
var byId = users.ToDictionary(u => u.Id, u => u.Name);

Async / Await

CSHARP 
public async Task<string> FetchDataAsync(string url)
{
    using var client = new HttpClient();
    var response = await client.GetAsync(url);
    response.EnsureSuccessStatusCode();
    return await response.Content.ReadAsStringAsync();
}

// Call async from async
public async Task RunAsync()
{
    string data = await FetchDataAsync("https://api.example.com/data");
    Console.WriteLine(data);
}

// Run from synchronous context
string result = FetchDataAsync("https://api.example.com").GetAwaiter().GetResult();

// Parallel async
var tasks = urls.Select(u => FetchDataAsync(u));
var results = await Task.WhenAll(tasks);

Security Relevance

C# appears frequently in Windows security tooling — both offensive and defensive. Understanding C# is useful for reading and writing:

  • Offensive: Cobalt Strike payloads, SharpHound, SharpUp, Rubeus, SafetyKatz, many LOLBIN-adjacent tools are C#
  • Defensive: EDR and SIEM connectors, Windows service wrappers, custom Sysmon parsers
  • Webshells: .aspx webshells are C# executed server-side on IIS

Tips

  • var does not mean dynamic — the type is still inferred at compile time and is fully static
  • Prefer record types for DTOs and value objects — immutability and value equality come for free
  • async void is almost always wrong except for event handlers — use async Task so exceptions can be caught and awaited
  • LINQ is lazy by default — call .ToList() or .ToArray() to force evaluation when you need all results immediately
  • Nullable reference types (<Nullable>enable</Nullable>) are worth enabling on new projects — the compiler warns on most null dereference bugs before they happen at runtime
