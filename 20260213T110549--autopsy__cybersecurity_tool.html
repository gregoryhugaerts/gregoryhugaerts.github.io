Open-source digital forensics platform — a GUI front-end for The Sleuth Kit and other forensic libraries. Primary tool for dead-box forensic analysis: examining disk images from potentially compromised systems. Automates artifact extraction (browser history, registry, LNK files, EXIF) and provides a timeline and keyword search over the full image.

Related: windows client DFIR DFIR Network Traffic Analysis

Workflow

TEXT 
1. Create Case — defines case name, number, examiner
2. Add Data Source:
   — Disk image (.dd, .E01, .vmdk, .vhd)
   — Local disk or partition
   — Logical files folder
3. Select Ingest Modules — choose what to auto-extract:
   — Hash Lookup
   — Keyword Search
   — Recent Activity (browser history, registry)
   — File Type Identification
   — EXIF Parser
   — Email Parser
4. Wait for ingest to complete (can take minutes to hours)
5. Review results in the tree and results panes
6. Tag artefacts as evidence
7. Generate Report (HTML, Excel, or PDF)

Key Analysis Areas

Timeline Analysis

Correlates timestamps from file system (MAC times), registry, browser history, and log files into a single chronological view.

TEXT 
Tools → Make Timeline
— Filter by date range to focus on incident window
— Event types: file activity, web activity, registry, log entries
— Export to CSV for external analysis

File System Analysis

TEXT 
Data Sources tree → navigate directory structure
— Deleted files shown with X icon — recoverable if not overwritten
— Unallocated space — may contain carved file fragments
— $MFT parsing — full NTFS metadata including timestamps

Keyword Search

TEXT 
Keyword Lists → add terms before ingest for indexed search
Or: Keyword Search → enter term → search after ingest

Useful terms to pre-index:
password, secret, api_key, token, cmd.exe, powershell,
base64, encoded, invoke-expression, bypass, wget, curl

Hash Lookup

TEXT 
Configure in Tools → Options → Hash Database
— NSRL (known good) — flag OS/application files as benign
— Custom hash set — flag known-malicious hashes

During ingest, HashLookup module marks files as:
Notable (malicious hash match) or Known (NSRL match, ignore)

Carving Deleted Files

TEXT 
Data Sources → [image] → $Unallocated Space
Right-click → Extract Files (carves based on file signatures)
Or use PhotoRec integration for broader carving

Command Line Alternative

For scripted or headless analysis, The Sleuth Kit tools underlie Autopsy:

SHELL 
# List file system info
fsstat image.dd

# List all files (including deleted)
fls -r image.dd

# Recover a specific file by inode
icat image.dd 12345 > recovered_file

# Create timeline from file system metadata
fls -r -m "/" image.dd > bodyfile
mactime -b bodyfile -d > timeline.csv

Tips

  • Run ingest modules selectively on first pass — all modules enabled on a large image can take hours; Recent Activity, Hash Lookup, and File Type ID cover most initial triage needs
  • The Timeline view is the fastest path to reconstructing what happened during an incident window — filter to ±1 hour around the suspected compromise time
  • Shell Bags persist for folders that no longer exist — check them for evidence of deleted directories or USB-connected drives
  • Notable hash matches (known-malicious) surface immediately in Results → Hashset Hits — check these before manual browsing
  • Autopsy case files are portable — the case directory contains all analysis results and can be shared with another analyst without re-running ingest
