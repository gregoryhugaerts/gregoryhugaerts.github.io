Accidental or intentional destruction, theft, corruption, or unavailability of data. Distinct from a data breach (unauthorised access) though the two often co-occur — ransomware simultaneously causes data loss (unavailability) and may involve a breach (exfiltration before encryption).

Data Loss Prevention (DLP)

Backups

The primary recovery control. The 3-2-1 rule:

TEXT 
3 copies of data
2 different storage media types
1 copy off-site (or in a different cloud region)

Backups are only as good as the last tested restore — run recovery tests regularly. Ransomware operators specifically target and delete backups before encrypting production data.

Access Control

Limit who can access, modify, and delete data. Applying Least Privilege reduces the blast radius of both insider threats and compromised accounts.

TEXT 
Controls:
— Role-based access (RBAC) — access by job function, not individual
— Separation of duties — no single person can both create and approve
— Audit logs — record who accessed or modified what and when
— Privileged access management (PAM) — elevate only when needed

DLP Software

Monitors and controls data movement — detects and blocks sensitive data leaving via email, USB, cloud upload, or print. Useful for preventing accidental sharing and insider exfiltration.

TEXT 
Common capabilities:
— Content inspection — detect PII, financial data, credentials in transit
— Endpoint control — block USB copy, screen capture, print
— Email scanning — flag or block outbound attachments matching patterns
— Cloud access security broker (CASB) — visibility into SaaS data flows

Encryption

Protects data from being readable if lost or stolen — a lost unencrypted laptop is a breach; a lost encrypted laptop is not. See Encryption.

Disaster Recovery

A documented, tested plan for restoring operations after a catastrophic data loss event.

TEXT 
Key metrics:
— RTO (Recovery Time Objective) — how long can we be down?
— RPO (Recovery Point Objective) — how much data loss can we accept?

A backup that takes 72 hours to restore is not useful if the
RTO is 4 hours.

Regulatory Implications

Data loss events involving personal data trigger notification obligations under GDPR and similar frameworks:

TEXT 
GDPR Article 33: Notify the supervisory authority within 72 hours
of becoming aware of a personal data breach.
GDPR Article 34: Notify affected individuals if the breach is
likely to result in high risk to their rights and freedoms.

Failure to notify within 72 hours is itself a GDPR violation, separate from the breach itself. The DPO (Data Protection Officer) must be involved immediately when a loss event is identified.

Tips

  • Test backup restores regularly — an untested backup is an assumption, not a control
  • Ransomware makes backup integrity critical — ensure backups are air-gapped or immutable, not accessible from the same network as production
  • The 72-hour GDPR notification clock starts from when the organisation "becomes aware" — internal reporting speed matters for compliance
  • Data classification is the prerequisite to meaningful DLP — you cannot protect data you haven't identified as sensitive
